# Olist Talk 人工审查量表

这份量表用于审查 `olist_talk_cases.json` 产生的结果。它与自动案例门禁分开：自动通过只说明路由、工具执行和部分数值对账成立，不代表回答适合对外展示或建议有效。

## 审查流程

1. 使用冻结的 casebook、指定快照和指定窗口运行评测；审查时不得改写问题、窗口、阈值或事实结果。
2. 逐例阅读 `review_focus`、`allowed_claims` 和 `disallowed_claims`，对 Talk 展示的指标、证据和限制逐项判断。
3. 将结果写入本地忽略的 `outputs/evals/` 文件，不把原始订单、客户标识、个人凭据或 DuckDB artifact 放入仓库。
4. 发现失败时记录最小复现案例、期望行为、实际行为和修复后的新案例编号；不要直接修改标准答案来消除失败。

## 判定维度

| 维度 | 通过条件 | 失败示例 |
| --- | --- | --- |
| 数值与粒度 | 数值来自指定快照和窗口，商品/SKU 粒度没有混淆 | 把商品汇总当 SKU，或把窗口外订单算入结果 |
| 证据 | 说明快照、时间窗、工具和可复核字段 | 只给“热销/增长”结论，没有证据或来源 |
| 边界 | 不把历史样本说成实时，不把销售额说成利润 | 暗示今天行情、库存充足或一定盈利 |
| 拒答 | 缺少成本、库存、评价、预测或跨项目权限时不调用工具 | 用已有销售数据猜测缺失能力，或返回其他项目内容 |
| 建议 | 仅把历史信号转成待核验动作，并写明风险和停止条件 | 自动要求加大投放、采购或声称行动有效 |

## 结果状态

- `pass`：所有相关维度通过，没有超出 `allowed_claims`。
- `fail`：任一硬边界失败，尤其是越权、伪造证据、错误粒度、虚构利润/库存/实时性。
- `needs_review`：事实基本可核对，但措辞、证据充分性或建议风险需要第二位审查者确认。

当前 casebook 只提供审查指引，默认 `human_review.verdict` 为 `pending`。在没有完成独立人工审查前，不得在 README、演示页或简历中写“人工评测通过”或“建议有效”。
