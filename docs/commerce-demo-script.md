# 电商 Benchmark 演示脚本

这条路径用于个人学习和求职展示。它验证商品销售、热点、趋势、选品建议、Talk 和 Plan
是否能围绕同一个不可变快照工作；Olist 是历史公开样本，不代表实时市场、利润、库存或建议效果。

## 演示前准备

1. 确认已依法取得 Olist CSV，并放在仓库外的本地目录；原始文件、DuckDB artifact 和本地数据库不提交 Git。
2. 在 `backend` 目录导入快照：

   ```bash
   .venv/bin/python -m scripts.import_commerce_benchmark <Olist数据目录>
   ```

3. 运行独立 Talk 对账：

   ```bash
   .venv/bin/python -m scripts.evaluate_olist_cases <Olist数据目录> --currency BRL
   ```

   自动通过只表示事实、路由和拒答边界可复核；人工审查仍需按[量表](../backend/evals/olist_talk_review_rubric.md)单独完成。
4. 启动后端和前端，打开 `http://127.0.0.1:3000/commerce`。若 `8000` 被其他 checkout 占用，按[开发运行手册](development-runtime.md)切换备用端口。

## 00:00-00:45 快照边界

登录后选择 Benchmark 快照，指出来源、覆盖时间、结构版本、内容指纹和能力声明。强调页面只读取
快照元数据与确定性聚合，不把订单明细直接暴露到公开页面。

## 00:45-01:40 商品与 SKU 粒度

在商品和 SKU 间切换，观察销售排行、趋势、热点和选品区域同步变化。提问“哪些 SKU 销售额领先？”，
说明商品与 SKU 是不同结果粒度，服务端会拒绝混用粒度的查询。

## 01:40-02:30 热点与趋势证据

查看当前窗口和基线窗口，解释热点标签来自销量领先、销售额领先、增长动量或多卖家覆盖，
而不是黑盒综合分数。展示品类趋势和商品趋势，说明变化率只描述历史窗口，不预测下一期。

## 02:30-03:20 Talk 语义门禁

依次提问：

- “哪些品类销售额增长了？”：调用品类趋势工具，展示指标代号、时间字段、订单状态和证据字段。
- “热销商品的利润是多少？”：拒答，因为 Olist 没有成本和利润事实。
- “今天哪些商品会爆款？”：拒答，因为历史快照不是实时数据，也不支持预测。

说明自然语言只映射到注册的 `QuerySpec`，模型不能提交任意 SQL；工具结果还会经过快照、粒度和窗口校验。

## 03:20-04:35 Plan 审批与演练

使用管理员账号切换到 Plan，生成一个商品经营计划草案。展示计划固定引用快照和证据，审批只改变计划
状态，不执行采购、改价、投放或外部平台动作。审批后追加一条 `benchmark_simulation` 情景和离线反思，
说明它不是商家真实执行结果，也不会回写销售事实。

用普通账号重新打开同一页面，确认只能使用 Talk，Plan 由服务端拒绝而不是仅靠按钮隐藏。

## 04:35-05:00 诚实结论

可以展示：历史销售事实可复核、指标语义有边界、工具失败会显式暴露、权限和模式有服务端门禁。
不能展示：实时行情、利润预测、库存判断、因果收益、跨平台泛化或真实商家行动效果。
