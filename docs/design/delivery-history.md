# Market Pilot 交付历史

本文压缩记录项目已完成的主要阶段。详细文件级变更保留在 Git 历史中，当前行为以代码、测试、
[发布基线](../release-baseline.md)和[设计索引](README.md)为准。

## 1. MVP 基础

首轮交付建立了可运行的双业务模块：

- 开店前：投资、租金、订单、客单、加盟和竞品风险测算。
- 开店后：订单、菜单成本和评论 CSV 清洗与经营诊断。
- FastAPI、SQLAlchemy、SQLite 和 pandas 后端。
- Next.js、React 和 TypeScript 前端。
- 确定性营收、菜品矩阵、评论主题、保本线、折扣、时段和渠道分析工具。
- Plan-and-Execute 报告生成、证据、风险和行动清单。
- 演示入口、完整报告页和 Windows 启动器。

## 2. 外部上下文

外部数据阶段建立了供应商无关的数据边界：

- 版本化城市和品类参考 JSON。
- 带来源、统计周期、单位和数据性质的参考指标契约。
- SQLite 外部上下文快照、有效期和精确键复用。
- 百度 Place API 客户端、标准化 POI DTO 和安全错误分类。
- 确定性竞争指标与证据输出。
- 原始供应商响应只在请求内处理，不进入长期报告和 Agent 提示词。

## 3. 选址能力

选址阶段交付两种入口：

- 手动模式分析一个地址或坐标。
- 自动模式在行政区内生成 3 至 5 个候选商圈。
- 多关键词、圈层和分页采集，以及 UID 去重。
- 候选聚类、特征构建、机会评分、可信度和警告。
- 商圈机会、财务可行性和数据可信度独立展示。
- 受环境变量保护的真实百度接口冒烟测试。

## 4. Agent 核心演进

Agent 演进按可测量性优先完成：

1. 建立 30 条离线规划与追问评测基线。
2. 为工具增加类型化状态、证据和安全错误契约。
3. 增加 full/focused 模式、最小工具集合和一次有界 Replan。
4. 增加 SQL 会话、项目档案、受限上下文和同口径历史指标。
5. 统一开店可行性、选址和经营诊断三个高层能力入口。
6. 增加角色模型配置、token/延迟/重试统计和安全运行追踪。
7. 完成架构、评估证据、五分钟演示和发布基线。

阶段完成时的验证结果为后端 `396 passed, 2 skipped`，30 条离线 Agent 用例通过，前端生产
构建和 Windows 启动器构建通过。后续菜品追问回归使后端用例增加到 397 条。

## 5. 当前设计方向

下一轮已批准的方向是[自适应证据追问](adaptive-evidence-followups.md)：

- 当前报告问题优先使用压缩证据包，避免模型手写指标路径。
- 缺失历史或外部事实时才进入有界 Plan-and-Execute。
- 回答分为门店数据、通用经营建议和缺失信息。
- 校验按结论执行，失败结论最多局部修复一次。
- 用户修改产生新回答版本，并可触发受限重新规划。
- 反馈提取为 SQL 结构化记忆，不保存自由文本反思文件。

## 6. 明确延期

- 向量数据库和通用文档 RAG。
- 第二地图供应商。
- 任意网页抓取、SQL、代码执行或文件读取工具。
- 无限 Agent 循环和多 Agent 协调。
- 多租户权限系统。
- 把选址评分解释为开店成功率。
