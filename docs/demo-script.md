# Market Pilot 五分钟 Agent 演示

## 演示目标

在五分钟内证明三件事：数值由确定性工具计算；Agent 会按问题选择工具并引用证据；
模型、数据或外部服务失败时系统能够安全降级。

## 演示前准备

1. 启动后端与前端，打开 `http://127.0.0.1:3000/demo`。
2. 为完整 Agent 路径配置一个 OpenAI-compatible 模型；不配置时仍可演示确定性降级。
3. 保持 `backend/sample_data/` 不变，先执行一次 `python -m scripts.run_agent_evals`。
4. 清空或备份本地数据库，避免历史项目干扰演示顺序。

## 00:00-00:30 定位与边界

讲解：

> Market Pilot 是面向餐饮单店的决策 Agent。它把开店可行性、商圈选址和经营诊断统一到
> 三项高层能力；营业额、毛利、保本线等由 pandas 工具计算，模型只负责受策略约束的规划、
> 综合和追问。所有数值结论都需要证据路径。

## 00:30-01:25 完整经营体检

1. 进入“经营诊断”。
2. 选择“完整体检”，保留问题“做一次完整经营体检”。
3. 点击“生成样例经营诊断”并打开完整报告。

指出报告中的营收、菜品、评论、时段、折扣、现金支撑和渠道贡献。打开 Agent 运行状态，
说明 full 模式执行所有输入可支持的核心工具，工具结果包含耗时、状态和证据。

## 01:25-02:05 聚焦问题与最小工具集

1. 返回经营诊断，选择“聚焦问题”。
2. 输入“中差评主要集中在哪些问题？”。
3. 生成报告并查看 Agent 运行状态。

预期只选择 `analyze_review_topics`，而不是为了表现“智能”执行全部工具。说明计划先经过
白名单和最小集合策略；非法计划会回退到确定性选择。

## 02:05-03:05 证据追问与结构化记忆

在完整体检报告底部连续追问：

1. “样本期总营收和订单量是多少？”
2. “那它和你刚才提到的客单价是什么关系？”

第一问应引用精确 `metrics.revenue.*` 路径；第二问读取最近公开对话保持指代连续性，但事实仍从
当前报告读取。说明数据库只保存公开问答，进入本轮上下文的历史项在追踪中只记录消息 ID。

## 03:05-03:35 缺基准时拒绝无依据判断

继续追问：

> “这个毛利率在行业里算高还是低？”

预期回答说明当前报告没有可信行业基准，不能直接判断高低；可以陈述当前值和需要补充的基准。
这是评估硬门禁，不是提示词中的礼貌措辞。

## 03:35-04:05 安全降级

在控制台清除 Agent 模型配置，重新运行一次样例经营诊断。系统仍返回确定性指标和报告，
运行模式显示 deterministic，fallback reason 说明 LLM 未配置。模型异常、Schema 不匹配或
证据校验失败也走同一类受控降级，不展示供应商原始错误或密钥。

## 04:05-04:35 统一生命周期能力

先通过 `POST /projects` 创建一个 `pre_open` 项目并记下返回的 ID。然后打开
`http://127.0.0.1:8000/docs`，调用 `POST /agent/analyze`：

```json
{
  "project_id": <pre_open_project_id>,
  "intent": "assess_feasibility",
  "inputs": {
    "category": "茶饮",
    "city": "成都"
  }
}
```

不完整输入应路由到 `pre_open_feasibility` 并返回 clarification 与精确缺失字段，不会启动底层
工具。补齐问卷后返回 completed。强调选址能力只能选择 manual/recommendations，不能控制
百度关键词、分页、评分权重、快照或事务。

## 04:35-05:00 量化证据

打开 [Agent 面试评估证据](interview-evidence.md)：

- 30 个离线案例；
- tool precision/recall/exact-set 均为 1.0；
- evidence validity 与 safety pass rate 为 1.0；
- unsupported numeric/normative claims 均为 0；
- 失败、token、延迟、重试和 request ID 有结构化追踪；
- 实时评估必须显式开启，避免意外消耗额度。

结束语：

> 这个项目的重点不是接了一个模型，而是让规划、工具、记忆、证据、失败和成本都能被约束、
> 测量和解释。

## 常见追问

### 为什么不用 LangChain？

当前只有有限工具和固定安全边界，轻量编排更容易测试每个状态和解释失败。未来需要跨系统
工作流时可以替换编排层，但确定性工具契约、记忆和评估不需要重写。

### 为什么不用向量数据库？

当前记忆是项目事实、公开消息和规范化指标，SQL 精确查询比语义相似度更可靠。合同或手册等
文档问答出现后再建立独立 RAG，不把经营记忆和知识检索混在一起。

### LLM 到底做了什么？

它在策略允许范围内选择 focused 工具、综合已验证指标、处理只读追问。它不计算指标、不执行
任意 SQL/代码、不读取任意文件，也不能操纵地图供应商底层参数。
