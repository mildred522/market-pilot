# 餐饮门店分析 Agent Demo Script

目标：在 5 分钟内演示这个项目不是聊天套壳，而是有业务分流、确定性指标计算、Agent 编排和报告输出的餐饮分析 MVP。

## 1. 开场介绍

一句话介绍：

> 这是一个面向餐饮小店的分析 Agent，分为开店前潜力分析和开店后经营诊断两个模块。系统用程序计算经营指标，用 Agent 做阶段路由、归因解释、证据校验和行动建议。

技术栈：

- Frontend：Next.js + React + TypeScript
- Backend：FastAPI + SQLAlchemy + SQLite
- Data：pandas
- Agent：轻量 Plan-and-Execute

## 2. 演示路径

打开：

```text
http://127.0.0.1:3000/demo
```

### Case A：开店前潜力分析

操作：

1. 点击“开店前：加盟奶茶店风险排雷”。
2. 使用页面默认问卷数据。
3. 点击“生成潜力分析”。
4. 点击“查看完整报告”。

讲解重点：

- 该模块面向准备开店的人。
- 输入包含投资、租金、预计订单、预计客单、加盟费、竞品数量。
- 后端先计算预估日营收、日毛利、日均房租。
- 报告重点提示负债、竞品密度和加盟投入风险。
- 行动建议不是泛泛建议，而是要求蹲点、估算竞品订单、核验加盟门店流水。

### Case B：开店后经营诊断

操作：

1. 返回 demo 页。
2. 点击“开店后：面馆经营诊断”。
3. 点击“生成样例经营诊断”。
4. 点击“查看完整报告”。

讲解重点：

- 该模块面向已经开店的人。
- 样例数据来自订单、菜品成本和评论 CSV。
- 营收、订单数、客单价由 pandas 工具计算。
- 菜品矩阵按销量和毛利分为明星、引流、利润、问题菜品。
- 评论主题提取配送、包装、出餐慢等问题。
- Agent 汇总工具结果，生成摘要、证据、风险和行动清单。

## 3. 架构讲法

可以按这条链路讲：

```text
React UI
  -> FastAPI API
  -> StageRouter 判断开店前/开店后
  -> Planner 生成分析计划
  -> Executor 调用 pandas 工具
  -> Synthesizer 生成诊断摘要
  -> Verifier 检查证据和行动建议
  -> Report UI 展示指标、证据、风险和动作
```

强调：

- 数值不由 LLM 猜。
- LLM/Agent 做规划和解释。
- 报告保留 evidence，方便解释结论来源。

## 4. 面试追问准备

### 为什么不用纯 LLM？

餐饮经营指标需要确定性计算。营业额、毛利、客单价、菜品销量应该由 pandas/SQL 计算，LLM 只负责归因和表达。

### 为什么分开店前和开店后？

两个阶段输入和结论完全不同。开店前关注可行性、选址、投资和加盟风险；开店后关注营收、菜品、评论、成本和整改动作。

### 为什么自己写 Agent Orchestrator？

MVP 里流程清楚、工具有限，自己写轻量 Plan-and-Execute 更容易解释，也避免过早引入 LangChain 复杂度。
